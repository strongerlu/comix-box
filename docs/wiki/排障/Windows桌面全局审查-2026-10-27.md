范围：当前工作区的 COMIC-BOX Windows 桌面源码，重点检查启动与后台进程、凭据保存、项目/对话切换、创作面板、文件读写、更新及测试入口。本次为审查，未修改业务源码、安装器或用户数据；并非全部功能的端到端验收，也未请求真实付费模型生成。

## 优先修复的问题

### P1：Windows 凭据存储实际使用 mock 后端

- 位置：`src-tauri/Cargo.toml:26`，`src-tauri/src/secure_store.rs:144`、`:219`、`:254`。
- `keyring = "3"` 未开启 `windows-native`；`cargo tree -e features -i keyring` 确认当前 Windows 构建只有 `default`。本机实际依赖 keyring 3.6.3 源码在未启用该特性时导出 mock 后端。
- 独立 Rust 探针只使用虚构服务和虚构密码：同一 Entry 写后可读，重新创建同名 Entry 就返回 `NoEntry`。不仅是重启不保存，每次 Rust 命令新建 Entry 都无法读取上次写入。
- 影响：Gateway 登录令牌、MCP OAuth、Comfy 凭据等不能依靠此路径持久化。主模型 API Key 的 UI 启动读取走 CLI 文件兜底，不能因此断言主 API Key 一定随重启丢失。
- 建议：为 Windows 明确启用原生凭据存储，补“不同 Entry + 进程重启”的持久化测试，核对旧凭据迁移后再发布。

### P1：创作面板可能沿用旧对话关联

- 位置：`src/components/memory/MemoryWorkbench.vue:4176`、`:2683`；`src/components/creation/CreationPanel.vue:942`、`:1087`、`:1124`。
- 打开面板时先捕获 active conversation，再等待异步加载；等待期间切到 B，随后仍将 A 的 origin 发给面板。面板保存该 origin，提交任务使用其中的 conversationId。
- 独立执行源码函数并用虚构 A/B 对话及延迟加载复现：当前对话为 B，发出的绑定仍为 A。没有接触实际会话或提交生成。
- 同一项目切换对话时，`selectConversation → openResource` 也没有同步更新面板 origin；`memoryMediaOrigin` 只在面板加载事件里赋值。
- 建议：绑定跟随当前对话，异步加载后检查对话版本；已提交的任务继续保留提交时 origin，不要被后续切换覆盖。

### P2：取消删除对话也会停止正在运行的任务

- 位置：`src/components/memory/MemoryWorkbench.vue:2709`。
- `stopRun(deletedRun)` 在 `confirmAction` 之前执行。用户点击删除、再取消，原任务已经中止。
- 对源码函数进行隔离执行，虚构运行任务与返回 false 的确认框，得到顺序 `["stopped", "cancelled"]`。
- 建议：先确认，再停止目标任务并删除；补取消操作不影响运行任务的行为测试。现有工作台源码匹配测试反而要求停止代码出现在确认消息之前，应一起调整。

### P2：FFmpeg 配置入口会误报就绪

- 位置：`src/utils/localCapabilities.ts:108`，`src/components/settings/LocalCapabilitySetup.vue:42`。
- `check()` 只读 `jc_ffmpeg_checked`，`setup()` 直接写 true 并派发 `jc-open-ffmpeg-setup`；当前源码没有该事件的接收方。
- 用虚构 localStorage 执行该模块，未安装或检测任何程序，setup 后 check 就从 false 变为 true。
- 影响：首次配置/能力中心可能显示已准备好，直到实际媒体操作才失败。
- 建议：接入真实 Windows 工具路径和版本检测；只有检测成功才显示就绪，并提供可用的安装引导。

### P2：后台媒体工具未统一隐藏 Windows 控制台

- 位置：`src-tauri/src/commands/dev.rs:2273`、`:2315`、`:2389`；`src-tauri/src/commands/http.rs:533`；`src-tauri/src/commands/tools.rs:18`。
- MCP 启动已有 `CREATE_NO_WINDOW`，但 FFmpeg 探测、缩略图、导出、FFprobe 下载校验和 Whisper 检测等调用未沿用。主程序 `main.rs` 的 release 子系统配置只控制主进程。
- 这是源码确认的缺口；本次未构建正式安装包复现每一种媒体操作的闪窗。
- 建议：复用统一后台进程配置，为用户主动打开的终端保留正常窗口；同时保留 stdout/stderr 日志。

### P2：API Key 文件保存失败会被隐藏

- 位置：`src-tauri/src/secure_store.rs:24`、`:204`；`src/services/newApiClient.ts:82`。
- CLI Key 文件是当前桌面 UI 的持久化读取源，但创建目录和写入均忽略结果，前端保存也吞掉异常。在目录只读、磁盘写入失败等条件下，界面内存已更新，却不能可靠提示保存失败；重启后仍可能读到旧值。
- 本项依据异常路径审查，未对用户真实密钥或目录进行故障注入。
- 建议：写入临时文件并原子替换、传回明确错误，成功后才向用户报告已保存。

## 优化建议

1. 大文件按需读取：`dev_read_file`、external read、批量 read 都先 `std::fs::read` 整文件，再截断；maxBytes 不能约束读取时的内存占用。使用 metadata + 有界读取，二进制和文本分开返回，避免同一数据同时转 UTF-8 与 Base64。现有截断文本不能进入编辑器的保护应保留。
2. 建立 Windows 测试入口：旧完整前端/脚本回归为 2319 通过、20 失败、28 取消、9 跳过（2026-10-26 运行记录，本次未重跑整套）。其中有 Bash 路径、硬编码 `/tmp`、Windows 分隔符的夹具问题，也有 SDK/创作行为失败，必须逐个分类，不能全部当作环境问题或直接跳过。
3. 降低维护耦合：工作台约六千行、创作面板约四千行，面板可见状态、对话归属和生成任务通过事件交叉维护。优先收敛对话与任务 origin 的单一来源，再逐步拆分职责；不建议以本次审查为由批量重构。
4. Lint 目前为 221 条 warning、0 条 error，多数是未使用变量、重复转义或数组展开。先处理影响错误处理与维护判断的告警，不能把告警数量当作 Bug 数量。

## 2026-10-28：可用性评估三项修复

用户要求处理本地可用性评估发现的并发保存、创作流程失败和中继慢握手。保留工作区已有修改，未改服务域名、账号或应用身份。

### 根因与处理

1. **Windows 并发保存**：`MoveFileExW` 在目标被不允许删除共享的句柄短暂占用时返回拒绝访问/共享冲突。原实现立即失败；现仅对 Win32 5、32、33 错误在最多一秒内重试原子替换，不先删除或截断目标。条件保存每次尝试前复核 revision，等待期间外部修改会返回 conflict，保留外部正文。持久占用仍明确失败，清理条件保存的临时文件；通用替换失败保留调用者的临时原件。
2. **创作流程**：`resourceRoots` 把第三方 Skill 包的父目录也纳入保护。Windows SDK 的 ACL 诊断 Skill 位于临时目录，其父目录恰好是整个 TEMP，使临时项目的原作读取、记录写入及流水线前置资料读取被误拒绝。现按 provider 给出的包目录精确保护；既有标准 Skill 根、符号链接和跨路线限制保留。另纠正同一实际 SDK 测试中的 Bash 固定假设及只识别 `/` 的绝对路径夹具，Windows 普通会话验证 `pwsh`，没有关闭或跳过失败的业务断言。新增外部包与同级项目的独立回归，旧守卫实测红灯。
3. **中继慢握手**：Windows 阻塞 socket 读超时为 `TimedOut`，tungstenite 只把 `WouldBlock` 保留为可续接的握手。改为同一连接上的非阻塞 TLS/WebSocket 握手，每15毫秒继续，20秒总期限保留，成功后恢复阻塞模式。新增永不回应时按总期限返回 `RELAY_TIMEOUT` 的测试；鉴权、离线错误与双向数据往返保留。

同时将 Rust Skill 数据库路径测试从旧 `.skillsmanage` 断言改为 `.comic-box/skillsmanage/db.sqlite`；运行时目录未变。

## 2026-10-28：付费全流程预检与 Windows 对话入口修复
