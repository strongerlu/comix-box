# COMIC-BOX 首帧续接调度接入（2026-10-29）

## 问题与本次范围

此前已有本地 H3 首帧请求入口、审片提帧和来源绑定，但全自动生成仍按普通参考图提交，无法单独指定后续段的首帧型号。初次接入补齐了 Windows 桌面调度与界面；随后按用户要求补齐通用分段关系规划和实际输入校验，并更新工程剧本与流水线 Skill，不绑定特定渠道或模型部署位置。

## 使用方式与行为

在「全自动·到成片」启动卡的「跨段续接」选择已声明首帧能力的型号，例如 `jc-MiniMax H3 首帧图生`。首段仍使用上面的「视频模型」；新段按工程稿登记的关系决定输入，动作接续才串行等待上一段成功，再从上一段实际采用的视频、按计划剪切点提取尾帧。切镜、换场景使用主视频型号和本段独立参考素材。

- 默认仍是「普通参考生成（各段独立）」。只提供普通参考图的型号不能充当首帧型号；未声明有效时长或不支持项目比例也会拦截。
- 首帧专用接口只上传尾帧，项目中原有角色、场景参考图与原提示词保留作为来源证据；实际提交提示词消除不存在的多图编号，审片版本中可以展开「实际提交内容」核对。明确允许参考图与首帧并存的接口则保留两者。
- 分段最长时长取两种型号共同支持的上限；固定时长档位同时受上限约束。按本地模型字段声明映射比例枚举和尺寸，避免把 `16:9` 直接发送给要求 `16:9 (Widescreen)` 的字段，或默用其他比例尺寸。
- 已生成的片段不会因选择续接而自动收费重做；需要时在审片中明确使用上一段尾帧重做。停止等待会保留已提交任务，续做先查询原任务；来源视频换版或续接型号不一致时拦截，不能悄悄退回普通参考生成。
- 明确配置续接时，成片拼接统一到首段画幅、24fps、48kHz 立体声音轨；缺音轨补静音。普通生成仍保留原复制拼接路径。此处理解决编码兼容性，不保证画面动作连续性或模型服从度。

## 通用分段规划与实际输入校验（后续优化）

新写或修改的分段在 `segments` 中登记 `transition:{type,reason}`，由工程设计判断，不通过关键词猜剧情，也不写进提交正文：

| type | 依据 | 选择续接型号时的输入 |
| --- | --- | --- |
| `continue` | 同一镜头、连续动作、兼容构图 | 等上一段成功，用实际切点尾帧 |
| `cut` | 反打、景别或观察侧改变 | 主型号、本段独立参考素材 |
| `scene_change` | 换场景或时间，本集开场 | 主型号、本段独立参考素材 |

关系必须有非空依据，首段不能 `continue`；保存进度和生成前均检查。未选续接能力时仍可按普通参考方式制作连续动作，不能假称实际提供了首帧。旧进度没有关系字段时保持原有续接设置；已完成文件不强制迁移或改写。关系依据保存在版本记录，版本对比可查看。

首帧专用提示词转换保留不同主体的编号、外观与声音描述，不再把所有主体都替换为同一个“首帧”。H3 多参考的六节原文转为单首帧的基础结构，保留镜头、对白、声音；原文与实际提交内容分别保存。未提供的视频/音频引用、混用图号语法和图号绑定错误会在提交前拦截。提交时读取同一份正文快照，再核对输入指纹，防止预检后编辑的文本沿用旧记录提交。

已有首帧段后来改成切镜时，系统要求明确普通重做以解除旧绑定；不会直接覆盖原视频。普通重做保留历史版本；用户仍可在审片中明确选择尾帧重做。预算按各段实际使用的型号估算，切镜段不套用续接型号价格。

本轮只落实优先级1、2以及相关版本保护；没有新增黑帧检测、自动视觉审片或通用质量评分，也未借测试调整某个影片的剧情。
