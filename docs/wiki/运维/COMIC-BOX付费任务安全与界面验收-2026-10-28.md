## 实施内容

- 调度器先保存 `request_id`，再调用提交；响应丢失后按该编号找回本地任务，不自动创建第二份付费请求。
- MCP 将请求编号、账号/项目作用域和参数指纹随任务持久保存；同一请求在冷恢复后仍返回原任务，参数变化则拒绝复用。作用域不写入明文 Key。
- 没有受理凭据的超时、中断或丢失记录标为 `uncertain`，在历史中显示“提交结果待核实”，提示原请求可能仍在生成。自动续做不重提此类请求；之后找回的成功结果可以继续复用。
- 有上游任务号的暂时性查询失败先恢复原任务查询。显式拒绝与受理不明分开处理，用户主动重做仍是新的生成行为。
- 付费前校验原作及已登记产物的 SHA256；视频片段必须从 0 开始连续、覆盖登记时长，并核对提示词参考图的编号、名称和顺序。所有片段先检查，再开始本集提交。
- 审图/审片面板明确修改某份提示词时，只更新该文件的检查点指纹；其他前置文件仍须一致。重新读取更新后的检查点，再只提交所选片段，未改片段沿用原结果。
- 修复续做阶段参数未传入文字指令的问题，避免已经完成的阶段被要求重写。
- 角色工程稿遵循项目横竖比例；H3 Skill 明确多视图只代表同一实体，舍弃设定图分格、标签和背景，按最终影片风格统一，并明确镜头中的实际人数。此文案不保证消除模型画面错误。
- 实测发现 NewAPI 将额度不足归入 SDK 的 `AUTH`；界面先识别真实额度信息，避免误显示“API 密钥无效”。普通无效 Key 仍保留原提示。

## 本次真实界面操作

使用 `computer-use` Skill 的 Windows `@oai/sky`，实际目标为本仓库 `src-tauri/target/debug/comic-box.exe`，未操作 Codex 界面。

1. 从项目中心“打开本地文件夹”打开独立空项目 `F:\code\ComicGen\tmp\comic-box-gui-e2e-20261028`。原成片项目保留。
2. 在应用模型菜单选择 Sonnet（`claude-sonnet-4-6`），从“创作 Skill → 小说创作”发送原创短篇要求。应用加载 `jc-novel`，生成《最后一盏灯》，保存章节草稿与根目录 `原作.md`。
3. 从同一菜单切换“短剧改编”，要求一集 15 秒、16:9、二维手绘、单人、无对白。第一次模型仅提出计划，需要再次明确执行；随后归档了梗概、总纲与逐章规划，但切分未通过。
4. 发现原短篇只有作品标题，没有可定位章标题。通过界面对应用发送修正要求，明确加载 `jc-duanju-pipeline`，将 AI 原作首行改为真实单章标题，保留正文，重新读取并按正式工具保存原文副本和检查点。没有普通写文件伪造切分或哈希。
5. 最初进度进入 `scheme`，来源副本和章节为“第一章 最后一盏灯”。模型切分参数不合合同，随后云端因额度不足中止。用户充值后，字段诊断修复并经界面继续正式切分，已完成一集 15 秒分集剧本，改编检查点进入 completed。
6. 修复错误文案后，实际界面显示“模型服务额度不足，请充值后继续；已保存的项目进度会保留”。未点击失败任务继续，未提交新的图片或视频请求。
7. 打开“任务记录”，实际确认之前超时且无受理号的角色图片显示“提交结果待核实”及重复计费提示；没有点击重新生成。
8. 将一集剧本通过漫剧入稿流程归档，确认 16:9、二维手绘、仅林舟一人、场景站台与信号灯三份参考图；修复入稿自动推进检查点的问题，界面复核确认检查点指纹未变。
9. 正式文字制作因道具资料没有登记到 materials 检查点而受阻。通过界面要求正式 plan/materials 修复，保留现有正文；补道具提示词，再完成工程剧本和 H3 两段 0–7、7–15 秒提示词。没有普通写文件绕过检查点校验。
10. 确认卡选择单集预算 5 元、审图与审片开启、H3 480p。人物图成功，灵动另两图长时间无返回；先停止调度，修复超时和部分审图恢复，再从卡片换小易 Flare 1K，显式重做两项。原任务的结果与扣费仍待核实。

12. 通过第二段“改提示词”，追加单一信号灯同物约束与更清楚的克制微笑；“保存并重新生成”只创建第二段新任务，第一段的任务号、累计提交数和 SHA256 不变，11 份登记文件的指纹校验通过。
13. 重新播放第二段，点击“确认并拼接”，由应用原生宿主生成 `wiki/成片/第1集成片.mp4`，状态 done。通过文件树打开播放；15.032 秒、854×480、24fps、H264/AAC、8,219,716 字节，完整解码无错误。SHA256 `5d6efd423bbb5ba02fbb743572bde2c2a37a504c9e9cd894da0da43c6275c01f`。
